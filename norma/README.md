# Норма — калькулятор виконання норми

Застосунок для телефона (і компʼютера): працівник вносить, що зробив за зміну, і бачить, на скільки відсотків
виконав норму, з урахуванням фактичного входу/виходу, перерви, простоїв та інших робіт. У кожного — свій
акаунт і своя статистика, а адміністратор бачить усіх працівників.

- **Адреса**: `https://<назва-проєкту>.web.app` (безкоштовно від Firebase; можна підключити й свій домен).
- **Вхід**: через Google або поштою з паролем. Реєструватися може кожен, хто має посилання.
- **Без кнопки «Зберегти»**: кожна зміна записується сама — на сервер, у свій акаунт; без інтернету —
  на телефон, і дописується, щойно звʼязок зʼявиться.
- **Адміністратор** (вкладка «Команда»): відсотки всіх працівників за місяць і сьогодні, хто ще не вніс день,
  попередження про підозрілі дні, статистика й історія кожного, звіт в Excel, закриття доступу.

Окремо є сторінка в claude.ai — той самий калькулятор, де дані лежать в особистому розділі акаунта Claude
(для себе; акаунтів працівників і адмін-панелі там немає).

## Що вміє калькулятор

**Сьогодні**
- шкала-«манометр» 0–150 % з позначкою норми, статус «до норми ще N шт»;
- **темп зміни наживо**: скільки мало бути зроблено зараз, чи випереджаєте графік, прогноз на кінець зміни;
- зміна одним дотиком (1 зміна, 2 зміна, Перша подовжена, Середня, свої, нічні) — від неї перерва;
  **вхід і вихід — фактичні, по прохідній** (кнопка «зараз» підставляє поточний час). Рахується саме різниця:
  вхід 6:30, вихід 14:15 → 7 год 45 хв − перерва 1 год = 6 год 45 хв, і норма на день пропорційно менша
  (35 шт → 33,75 шт). Видно, на скільки день коротший чи довший за графік;
- вироби: норма за зміну + кількість (кнопку «+» можна втримувати); «Мої вироби» зі скороченою назвою
  й нормою додаються одним дотиком;
- **приблизна норма**, якщо офіційної ще немає: поле з «≈», відсотки теж з «≈»; коли норма зʼявиться —
  «Уточнити», і всі дні з приблизною нормою цього виробу перераховуються (з попереднім показом,
  як зміниться середнє за місяць);
- **простій** і **інші роботи** — зі списку, з вибором хвилин; інші роботи зараховуються година в годину;
- «Як пораховано» з повною формулою і «Скопіювати підсумок дня»;
- **мета на місяць**: середнє з 1-го числа, скільки бракує до мети, скільки треба в середньому в решту
  робочих днів і скільки штук зробити сьогодні, щоб іти за планом;
- «Сьогодні серед інших днів»: порівняння з попереднім днем, середнім і рекордом, місце в місяці, серія;
- попередження, якщо відсоток неправдоподібний (понад 250 %: простій «зʼїв» зміну, помилка у вході/виході
  чи зайва цифра в кількості).

**Статистика** (тиждень / місяць / рік): середнє і зміна до попереднього періоду, мета місяця з підказками,
серії, рекорд, календар, карта року, графік з лінією ковзного середнього і позначкою тенденції, по тижнях,
«Цікаве» (тенденція, план на місяць, найкращі дні тижня, зміни й вироби, втрати від простою), куди пішов час,
причини простою, експорт в Excel.

**Історія**: усі дні по місяцях; будь-який можна відкрити, перевірити розрахунок, змінити чи видалити.

**Налаштування**: акаунт (імʼя, вихід), особиста мета, мета на місяць, робочі дні тижня, «норму задано на»
(за замовчуванням 7 год), зміни, мої вироби, причини простою, види інших робіт, тема, резервна копія у файл
і відновлення, експорт в Excel, видалення всіх даних.

## Команда (для адміністратора)

- Середнє команди за місяць (зважене за робочим часом), скільки людей внесли дні, скільки з нормою,
  скільки внесли сьогодні.
- Список працівників: середнє за місяць і зміна до минулого місяця, сьогоднішній відсоток, кількість днів,
  позначки «⚠» (неправдоподібні дні) і «≈» (приблизні норми). Фільтри «Нижче норми», «Сьогодні без запису»,
  «Попередження»; пошук; сортування за відсотком, імʼям, активністю; будь-який місяць.
- Картка працівника: його статистика й історія — ті самі екрани, що бачить він, лише для перегляду.
- **Закрити доступ**: працівник одразу бачить «Доступ закрито» і не може нічого записати; дані лишаються.
- **Адміністратори**: додати чи прибрати інших (за поштою Google).
- **Excel за місяць**: аркуш «Команда» (підсумок кожного) і «Дні» (усі дні всіх працівників).

## Хто що бачить

- Працівник бачить **лише свої** дні. Інших працівників і їхніх даних він не бачить.
- Адміністратор бачить профілі й дні **всіх** — і змінити чужі дні не може (лише закрити доступ).
- Про це сказано на екрані входу й у налаштуваннях кожного працівника.
- Це перевіряють **правила на сервері** ([`firestore.rules`](firestore.rules)), а не сама програма, тож обійти
  їх, змінивши код у браузері, не вийде. Адміністратор має підтверджену пошту (вхід через Google), тож
  зареєструватися поштою адміністратора й отримати його права неможливо.
- Дані лежать у вашому власному проєкті Firebase (сервіс Google), не в цьому репозиторії.
- На спільному телефоні дані різних акаунтів не змішуються, а після виходу з акаунта прибираються з телефона.

Правила перевірено автотестами (`npm run test:rules`).

## Як рахується

Норма виробу задана на стандартну зміну: 8 год − 60 хв перерви = **7 год (420 хв) чистого часу**
(змінюється в налаштуваннях). Фактичний день може бути будь-яким — норма перераховується пропорційно.

```
Робочий час     = (вихід − вхід) − перерва − простій
Норма на день   = норма × (робочий час − інші роботи) / 420
Виконання, %    = (нормо-час виробів + інші роботи) / робочий час × 100
```

Для одного виробу без інших робіт це просто «зроблено / норма на день × 100». Приклади для норми 35 шт:

| Вхід–вихід | Перерва | Простій | Робочий час | Норма на день |
|---|---|---|---|---|
| 6:30–14:30 | 60 хв | — | 7 год | 35 шт |
| 6:30–14:15 | 60 хв | — | 6 год 45 хв | 33,75 шт |
| 6:30–14:30 | 60 хв | 30 хв | 6 год 30 хв | 32,5 шт |
| 8:00–17:00 | 60 хв | — | 8 год | 40 шт |

Середнє за місяць — не середнє відсотків, а сума нормо-часу, поділена на суму робочого часу: довший день
важить більше.

## Налаштування (один раз, приблизно 15 хвилин, зручніше з компʼютера)

Потрібен Google-акаунт. Firebase на безкоштовному тарифі **Spark** (без банківської картки) з великим запасом
вистачає на десятки працівників.

### 1. Створіть проєкт Firebase — від нього залежить адреса

1. Відкрийте <https://console.firebase.google.com> → **Create a project**.
2. Назва — наприклад `norma-ceh`. Під полем видно **ID проєкту** — це і буде адреса:
   `https://norma-ceh.web.app`. Якщо назву зайнято, Firebase додасть хвіст (наприклад `norma-ceh-1a2b3`);
   ID можна змінити олівцем біля нього. Google Analytics — вимкнути. **Create project**.

### 2. Увімкніть вхід

1. **Build → Authentication → Get started**.
2. **Sign-in method → Google → Enable**, оберіть свою пошту як support email → **Save**.
3. **Add new provider → Email/Password → Enable** (лише перший перемикач) → **Save**.

### 3. Створіть базу даних

1. **Build → Firestore Database → Create database**.
2. Розташування — найближче, наприклад `europe-central2 (Warsaw)`; режим **production** → **Create**.

### 4. Ключ для автоматичної публікації

1. ⚙ **Project settings → Service accounts → Generate new private key → Generate key** — завантажиться
   файл `.json`. Це ключ доступу: нікому його не пересилайте.
2. Дайте цьому ключу право публікувати сайт: відкрийте
   `https://console.cloud.google.com/iam-admin/iam?project=<ID проєкту>`, у рядку
   `firebase-adminsdk-…@<ID>.iam.gserviceaccount.com` натисніть олівець → **Add another role** →
   **Firebase Admin** → **Save**.

### 5. Передайте ключ і свою пошту в GitHub

На сторінці репозиторію на GitHub: **Settings → Secrets and variables → Actions**.

1. Вкладка **Secrets → New repository secret**: Name `FIREBASE_SERVICE_ACCOUNT`, у Secret вставте **весь
   вміст** файлу `.json` (відкрийте його Блокнотом, виділіть усе, скопіюйте) → **Add secret**.
   Після цього файл з компʼютера можна видалити.
2. Вкладка **Variables → New repository variable**: Name `ADMIN_EMAIL`, Value — ваш Gmail (з ним ви
   входитимете як головний адміністратор) → **Add variable**.

### 6. Опублікуйте

1. На GitHub: **Actions** (якщо попросить — **I understand my workflows, go ahead and enable them**) →
   **Публікація на Firebase → Run workflow** → гілка `claude/worker-norm-calculator-ij740l` → **Run workflow**.
2. За 2–3 хвилини зʼявиться зелена позначка, а в підсумку — адреса `https://<ID>.web.app`.

Далі публікація запускається сама після кожного оновлення калькулятора — нічого робити не треба.
Налаштування веб-застосунку (`docs/config.js`) публікація теж заповнює сама.

### 7. Перший вхід і запрошення працівників

1. Відкрийте адресу, натисніть **Увійти через Google** і оберіть пошту з `ADMIN_EMAIL` — зʼявиться
   вкладка **Команда**.
2. Надішліть посилання працівникам. Вони реєструються через Google або поштою з паролем (імʼя та прізвище
   обовʼязкові — так вони підписані в «Команді»).
3. На телефоні калькулятор можна додати на головний екран: Android/Chrome — меню ⋮ → **Додати на головний
   екран**; iPhone/Safari — **Поділитися → На початковий екран**.

## Корисно знати

- **Безкоштовні ліміти** Spark: 50 000 читань і 20 000 записів бази на день, 1 ГБ даних — для калькулятора
  це сотні працівників. Якщо колись не вистачить, Firebase попередить листом.
- **Свій домен** (наприклад `norma.com.ua`): Firebase → **Hosting → Add custom domain** і запис у
  реєстратора домену — Firebase покаже, який саме.
- **Забули пароль**: на екрані входу «Забули пароль?» — прийде лист для зміни.
- **Видалити працівника повністю** (а не лише закрити доступ): Firebase → **Authentication** → рядок з
  поштою → **Delete account**, і **Firestore → users →** документ працівника → **Delete document**.
- **Дані зі старого калькулятора**: якщо на тому самому телефоні калькулятор уже був без акаунта, після
  входу він запропонує перенести ці дні в акаунт. Зі сторінки в claude.ai — «Налаштування → Зберегти
  резервну копію», а у вебверсії «Налаштування → Відновити з копії».
- Поки публікацію не налаштовано, сайт у `docs/` працює як простий калькулятор без акаунтів (дані лише
  на телефоні).

## Для розробника

Код — у `norma/src/calc` (Preact; сервер — Firebase Auth + Firestore, без власного бекенду).

- `App.jsx` — застосунок; сховище даних підключається через `backend` (`web.jsx` — Firebase з акаунтами,
  `main.jsx` — сторінка claude.ai зі сховищем Claude). Синхронізація спільна: `cloud.js` (документ
  налаштувань + документ на місяць, позначки видалення, повтори), памʼять телефона — `store.js`.
- `fb.js` — вхід, профіль, адаптер Firestore для `cloud.js`, запити адміністратора; `Team.jsx`, `team.js` —
  вкладка «Команда»; `Auth.jsx` — вхід і реєстрація; `model.js` — розрахунки й аналітика.
- `firestore.rules` — правила доступу; `__OWNER_EMAIL__` підставляє публікація зі змінної `ADMIN_EMAIL`.
- `../firebase.json`, `../.github/workflows/deploy.yml` — хостинг і автопублікація.

```bash
cd norma
npm install
npm run build        # вебверсія → ../docs, сторінка для claude.ai → dist/calc-artifact.html
npm test             # формули, аналітика, синхронізація, Excel
npm run test:rules   # правила доступу на емуляторі Firestore (потрібна Java 21+)
```

Локальний запуск з емуляторами: `npm run emulators` (у `firestore.rules` тимчасово впишіть тестову пошту
замість `__OWNER_EMAIL__`), віддайте папку `docs` статичним сервером і відкрийте
`http://localhost:<порт>/?emu`. Вхід «через Google» в емуляторі — з консолі браузера:
`__emuGoogle('boss@example.com', 'Імʼя')`.
