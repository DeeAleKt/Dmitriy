# Норма — розрахунок виконання норм виробітку

Вебзастосунок для телефона (і комп’ютера), який рахує, на скільки відсотків працівник виконав денну норму,
з урахуванням простоїв, і веде журнал зі звітами.

- **Розрахунок**: обираєте зміну (1 зміна, 2 зміна, подовжена… або свій час), виріб (пошук, групи,
  нещодавні), вводите кількість і простій — відсоток рахується одразу. Можна кілька різних виробів за день. Видно, скільки ще штук до 100 %, і є кнопка «Як пораховано»,
  де показано кожен крок формули.
- **Журнал**: записи за тиждень, місяць або довільний період, середній % і графік по днях. Адміністратор бачить
  підсумок по кожному працівнику і може вивантажити все в **Excel** (аркуші «Підсумок», «По днях», «Вироби»).
- **Керування** (лише адміністратор): довідник виробів з нормами (можна вставити одразу весь список з Excel),
  список доступу, зміни з часом початку, кінця і перервою.
- Встановлюється на головний екран телефона як звичайний застосунок. Є світла й темна тема.

## Офлайн-калькулятор (без сервера й конфіденційних даних)

Окремий застосунок-калькулятор для телефона: `norma/src/calc/` → збирається в один файл
`docs/calc/index.html` (після ввімкнення GitHub Pages — <https://deealekt.github.io/Dmitriy/calc/>).

Власного сервера в нього **немає**. Кнопки «Зберегти» теж немає: кожна зміна записується сама за секунду.
Де лежать дані:

- **Відкрито як сторінку в claude.ai** (з правом запису — власник, редактор, учасник Team-плану на рівні
  Contributor): в особистому розділі акаунта Claude `data/users/<id>/` — його не бачить ніхто інший, навіть
  власник сторінки. Дані однакові на всіх пристроях під цим акаунтом, а браузер телефона тримає копію-кеш.
  Під час першого входу все, що вже було на телефоні, переноситься в акаунт.
- **Деінде** (GitHub Pages, збережений файл, або сторінка без права запису): лише в браузері телефона
  (localStorage, з проханням до браузера не витирати його). Раз на два тижні калькулятор нагадує зберегти
  резервну копію у файл.

Індикатор під шкалою показує стан: «Зберігаю…», «Збережено», «На телефоні»; дотик відкриває пояснення.
Якщо закрити застосунок одразу після введення, день дописується при закритті або при наступному запуску.

**Сьогодні**
- шкала-«манометр» 0–150 % з позначкою норми, статус «до норми ще N шт»;
- **темп зміни наживо**: за годинником показує, скільки мало бути зроблено зараз, чи випереджаєте графік і
  прогноз на кінець зміни;
- зміна одним дотиком (1 зміна, 2 зміна, Перша подовжена, Середня або свій час, також нічна);
- вироби: норма за зміну + кількість (кнопку «+» можна втримувати); популярні вироби зберігаються зі
  скороченою назвою й нормою та додаються одним дотиком; раніше введені вироби пропонуються самі;
- **простій** і **інші роботи** — зі списку причин/видів робіт і з вибором хвилин (5 хв … 4 год, «уся решта
  зміни», точний час); одразу видно, як зміниться відсоток; списки можна доповнювати своїми пунктами;
- інші роботи зараховуються година в годину (7 год інших робіт при 7 год роботи = 100 %);
- «Як пораховано» з повною формулою і кнопкою «Скопіювати підсумок дня» (щоб надіслати в месенджер);
- **«Сьогодні серед інших днів»**: порівняння з попереднім днем, середнім за 30 днів і рекордом, місце дня
  в місяці, серія днів з нормою;
- конфеті й повідомлення, коли досягаєте мети (з довжиною серії) чи б'єте свій рекорд; новий день
  автоматично бере зміну й вироби з попереднього.

**Статистика** (тиждень / місяць / рік): середній відсоток і зміна до попереднього періоду, поточна й
найдовша серія днів з нормою, рекорд, календар місяця з кольором кожного дня, карта року з 12 міні-календарів,
графік по днях або місяцях з **лінією ковзного середнього за 5 днів** і позначкою тенденції («+2,5 % за
тиждень»), **по тижнях** із приростом від тижня до тижня, «Цікаве»: тенденція (лінійна регресія), скільки
треба в середньому в решту робочих днів, щоб закрити місяць на мету, скільки з 10 останніх днів з нормою,
найкращий і найважчий день тижня, зміна і виріб, скільки виробів «забрав» простій, найдовша серія; куди
пішов час, причини простою, види інших робіт, що робили. Поточна зміна, поки триває, не псує серію,
тенденцію й план. Експорт в Excel. Щоб одразу побачити, як це виглядає, є
кнопка «Подивитися на прикладі» (вигадані дні, позначені й прибираються одним дотиком).

**Історія**: усі збережені дні по місяцях; будь-який можна відкрити, перевірити розрахунок, змінити чи видалити.

**Налаштування**: особиста мета (від неї кольори й серії), «норму задано на» (за замовчуванням 7 год),
зміни, мої вироби, причини простою, види інших робіт, тема, резервна копія у файл і відновлення (для
перенесення на інший телефон), експорт в Excel, видалення всіх даних. Дані першої версії калькулятора
переносяться автоматично.

```bash
cd norma
npm run build:calc   # лише калькулятор → ../docs/calc/index.html і dist/calc-artifact.html
```

## Демо без налаштувань

`npm run build` також збирає демо-версію: той самий інтерфейс без Firebase і входу, з вигаданими виробами,
людьми й записами за останні тижні. Дані демо зберігаються лише в браузері того, хто його відкрив. У меню
акаунта можна перемикатися між власником і працівником, щоб побачити, хто що бачить.
Після увімкнення GitHub Pages демо буде за адресою <https://deealekt.github.io/Dmitriy/demo/>.

## Як рахується

Норма виробу задана на стандартну зміну: 8 год − 60 хв перерви = **7 год (420 хв) чистого часу**.
Фактична зміна може бути будь-якою — норма на день перераховується пропорційно часу роботи.

```
Час роботи      = (кінець зміни − початок) − перерва − простій
Норма на день   = норма × час роботи / 420
Виконання, %    = зроблено / норма на день × 100
```

Приклади для виробу з нормою 35 шт:

| Зміна | Перерва | Простій | Час роботи | Норма на день |
|---|---|---|---|---|
| 1 зміна, 6:30–14:30 | 60 хв | — | 7 год | 35 шт |
| 1 зміна, 6:30–14:30 | 60 хв | 30 хв | 6 год 30 хв | 32,5 шт |
| Середня, 8:00–17:00 | 60 хв | — | 8 год | 40 шт |
| Перша подовжена, 6:30–17:00 | 60 хв | — | 9 год 30 хв | 47,5 шт |
| 12 годин, 7:00–19:00 | 90 хв | — | 10 год 30 хв | 52,5 шт |

Зроблено 20 шт на 1 зміні з простоєм 30 хв → 20 / 32,5 = **61,5 %**.

Якщо за день робили кілька різних виробів, кожна штука «заробляє» 420 / норма хвилин нормо-часу, а виконання —
це сума нормо-часу, поділена на час роботи. Для одного виробу це дає той самий результат, що й формула вище.

**Зміни.** Готові зміни (за замовчуванням 1 зміна 6:30–14:30, 2 зміна 14:30–22:30, перша подовжена 6:30–17:00,
середня 8:00–17:00, у всіх перерва 60 хв) адміністратор налаштовує в «Керування → Зміни»: назва, початок, кінець,
перерва. Нічна зміна (кінець раніше за початок, напр. 22:30–6:30) рахується правильно. Працівник обирає зміну
одним дотиком угорі екрана розрахунку; там же можна вказати свій час і перерву саме для цього дня. Нова зміна
за замовчуванням — та, яку працівник обирав минулого разу.

## Конфіденційність

- Вироби, норми і журнал зберігаються **не в цьому репозиторії**, а в базі Firebase Firestore (сервіс Google)
  у вашому власному проєкті. У публічному коді немає жодних ваших даних.
- Увійти можна лише через Google-акаунт, і лише якщо його адресу додано в «Керування → Доступ».
  Це перевіряють **правила на сервері** (`firestore.rules`), а не сама програма, тож обійти їх, змінивши код
  у браузері, не вийде.
- Працівник бачить довідник виробів і **тільки власні записи**. Адміністратор бачить усе.
- Якщо вимкнути людині доступ, він зникає миттєво — навіть якщо програма в неї відкрита.
- На телефоні дані не зберігаються: після виходу з акаунта нічого не лишається.
- Власник (ваш Gmail, вписаний у правила) завжди має права адміністратора — випадково заблокувати себе неможливо.

Правила перевірено автотестами (`npm run test:rules`, 19 сценаріїв: сторонні, заблоковані, працівник,
адміністратор, власник, спроби підробити запис).

## Налаштування (один раз, приблизно 15 хвилин)

Потрібен Google-акаунт. Firebase на безкоштовному тарифі Spark (без банківської картки) з великим запасом
вистачає на десятки працівників.

### 1. Створіть проєкт Firebase

1. Відкрийте <https://console.firebase.google.com> → **Create a project** (Створити проєкт).
2. Назва — будь-яка, наприклад `norma-ceh`. Google Analytics можна вимкнути.

### 2. Увімкніть вхід через Google

1. **Build → Authentication → Get started**.
2. Вкладка **Sign-in method** → **Google** → **Enable** → вкажіть свою пошту як support email → **Save**.
3. Вкладка **Settings → Authorized domains → Add domain** → впишіть `deealekt.github.io`.

### 3. Створіть базу даних

1. **Build → Firestore Database → Create database**.
2. Редакція **Standard**, розташування — найближче, наприклад `europe-central2 (Warsaw)`.
3. Режим **Production mode** (усе закрито, доки не опубліковано правила).

### 4. Опублікуйте правила доступу

1. Відкрийте файл [`firestore.rules`](firestore.rules) і скопіюйте весь текст.
2. Знайдіть рядок з `'OWNER_EMAIL'` і замініть `OWNER_EMAIL` на ваш Gmail **малими літерами**
   (лапки залиште): `myEmail() == 'ivan.boss@gmail.com'`.
3. У Firebase: **Firestore Database → Rules** → видаліть старий текст, вставте свій → **Publish**.

> Простіший шлях: зробіть кроки 5–6, відкрийте програму і увійдіть. Вона покаже «Немає доступу» і кнопку
> «Я власник і налаштовую програму вперше» — там правила вже з вашою адресою, лишиться натиснути
> «Копіювати правила» і вставити їх у Firebase.

### 5. Під’єднайте програму до Firebase

1. У Firebase: ⚙ **Project settings → General → Your apps** → значок **`</>`** (Web) → назва будь-яка →
   **Register app** (Firebase Hosting вмикати не треба).
2. Firebase покаже блок `const firebaseConfig = { ... };` — скопіюйте його.
3. На GitHub відкрийте файл [`docs/config.js`](../docs/config.js) → олівець **Edit** → замініть блок
   `const firebaseConfig = { ... };` на скопійований → **Commit changes**.

   (Або просто надішліть цей блок мені в чат — я вставлю. Ці значення не є секретом: дані захищають правила
   з кроку 4.)

### 6. Опублікуйте сайт на GitHub Pages

1. Репозиторій на GitHub → **Settings → Pages**.
2. **Source: Deploy from a branch**, гілка `claude/worker-norm-calculator-ij740l` (або основна гілка,
   якщо ви злили зміни в неї), папка **`/docs`** → **Save**.
3. За 1–2 хвилини програма буде за адресою **<https://deealekt.github.io/Dmitriy/>**.

### 7. Перший вхід

1. Відкрийте адресу і увійдіть своїм Gmail (тим, що вписали в правила) — ви автоматично станете адміністратором.
2. **Керування → Зміни**: перевірте час і перерву кожної зміни (за замовчуванням усюди 60 хв) і, якщо
   потрібно, додайте свої.
3. **Керування → Вироби → Імпорт з Excel**: виділіть у таблиці стовпці «Назва» і «Норма» (за бажанням ще «Код»
   і «Група»), скопіюйте і вставте. Або додавайте вироби кнопкою «Додати».
4. **Керування → Доступ → Додати людину**: Gmail працівника, ім’я, роль. Кнопка «Посилання» надішле адресу
   програми в месенджер.
5. Працівник відкриває посилання на телефоні, входить своїм Google-акаунтом і, за бажання, додає програму
   на головний екран (меню акаунта → «Встановити на телефон»).

## Корисно знати

- **Індекс бази.** Якщо в журналі з’явиться повідомлення «Базі потрібен індекс», натисніть «Створити індекс»
  (під акаунтом власника) і зачекайте кілька хвилин — це одноразово.
- **Зміна норми чи змін** не переписує історію: у кожному записі збережено норму, час зміни і перерву, що діяли
  того дня. Якщо норму змінили,
  а запис ще редагують, програма підкаже «Норму змінено — оновити».
- **Виріб, що більше не випускається**, краще перенести в архів (у картці виробу), ніж видаляти.
- **iPhone**: якщо вхід через Google не спрацьовує з іконки на головному екрані, увійдіть один раз у Safari.
- **Додатковий захист (необов’язково)**: у Google Cloud Console → APIs & Services → Credentials обмежте
  ключ «Browser key» адресами `https://deealekt.github.io/*` та `https://<ваш-проєкт>.firebaseapp.com/*`.

## Для розробника

Код — у `norma/src` (Preact + Firebase, без серверної частини). Зібрана програма лежить у `docs/`, її віддає
GitHub Pages. `docs/config.js` збірка не перезаписує.

```bash
cd norma
npm install
npm run build        # збірка в ../docs
npm test             # формули, аналітика, синхронізація з акаунтом і генератор Excel
npm run test:rules   # правила доступу на емуляторі Firestore (потрібна Java 21+)
```

Локальний запуск з емуляторами: `npm run emulators` (правила з `firestore.rules` — впишіть тестового власника),
у другому терміналі віддайте папку `docs` будь-яким статичним сервером і відкрийте
`http://localhost:<порт>/?emu`. У режимі емулятора вхід — через консоль браузера:
`__emuSignIn('boss@example.com', 'Ім’я')`.
